## 2. 핵심 학습 (개념 정리)

### tick의 의미
- **tick = "지금 한 번 실행해봐" 신호**
- 노드는 SUCCESS / FAILURE / RUNNING 셋 중 하나로 응답
- 매 주기 루트부터 호출, 부모는 자식 결과로 다음 행동 결정

### Sequence vs Fallback
- **Sequence (AND)**: 자식 SUCCESS → 다음, FAILURE → 즉시 멈춤
- **Fallback (OR)**: 자식 FAILURE → 다음, SUCCESS → 즉시 멈춤

### Alarm 패턴 (Nav2 표준)
- `SUCCESS = 임무 수행`이지 `검사 통과`가 아니라는 점이 핵심
- SafetyCheck의 임무는 "위험 발견" → 정상이면 발견 못 했으니 FAILURE

### StatefulActionNode
- `onStart()` → 첫 tick (보통 RUNNING)
- `onRunning()` → 후속 tick (작업 중이면 RUNNING, 끝나면 SUCCESS/FAILURE)
- `onHalted()` → 외부 abort (예: Nav2 cancel goal)
- W2에서 Nav2 Action Client로 마이그레이션 시 클래스 타입 변경 없이 본문만 채우면 됨

### funnel = 호객 6단계
1. IdleScan — 고객 후보 탐지
2. Approach — Proxemic 거리(1.5m) 접근
3. IceBreak — 인사 발화
4. Minigame — RPS 친밀감 빌드업 (Phase 3)
5. Offer — 메뉴 제안
6. LeadIn — 카운터 안내

## 3. 발견 / 위험 요소 / 갭

### 발견
- **빌트인 노드 41개 자동 등록**: BehaviorTree.CPP 4.8.3의 BehaviorTreeFactory 생성자가 Sequence/Fallback/Parallel/decorators 등을 자동 등록. 사용자 노드는 별도 카운트로 관리하는 게 디버깅에 유리
- **symlink-install의 위력**: XML/launch 파일은 빌드 0.17s에 갱신. BT 구조 실험 사이클 매우 빠름
- **Phase 0-B 산출물 정합성**: dobi_npc_bt 패키지가 Phase 1 가정과 정확히 일치 (이름, build_type, 의존성). Phase 0-B에서 미리 잡아둔 것이 W1 진행을 매끄럽게 함

### 위험 요소
- **launch 인자 ↔ cpp 미연동**: `xml_file:=funnel_v2.xml` 줘도 cpp가 무시. W2에서 `node->declare_parameter("bt_xml_path", default)` 추가로 활성화 예정
- **Groot2 검증 미실시**: BT XML이 시각화 도구로 검증되지 않음. W2 시작 전 Groot2로 1회 시각화하면 디버깅 비용 절감 예상
- **tick 루프 미구현**: 현재는 tickOnce() 1회만. RUNNING이 SUCCESS로 끝나는 완전한 흐름 미확인. C-5 (별도 작업)으로 처리

### 갭 (계획서 W1 명세 vs 실제)
- 계획서 "BT 노드 6개" → 실제 **7개** (SafetyCheck를 명시적 헤더로 분리)
- 계획서 SafetyCheck 시맨틱 미명시 → **Alarm 패턴으로 명문화** (`SUCCESS = 위험 발견`)
- 헤더-only 패턴 채택 (cpp 분리는 W2/W3 노드별 로직 추가 시점에)
