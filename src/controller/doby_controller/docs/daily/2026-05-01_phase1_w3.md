## 1. 작업 흐름 (시간순)

### Step 1: 페르소나 YAML 4종 작성

`src/dobi_npc/dobi_npc_dialog/config/personas/`:

- `generic.yaml` — 베이스. 모든 자식이 상속. Proxemic(1.5m, 1.0m abort), Phrase 기본값, face_expression 매핑.
- `casual_browser.yaml` — 부담 없는 톤, 가벼운 권유. (parent: generic)
- `friendly_child.yaml` — 활기찬 톤, approach_distance 1.2m로 단축, fun/happy 표정. (parent: generic)
- `professional_adult.yaml` — 정중 존댓말, approach_distance 1.8m로 확대, basic 표정. (parent: generic)

**YAML 데이터 모델**:
```yaml
parent: generic               # 상속
persona_id: <unique>          # 식별자
display_name: <human-readable>
approach_distance: 1.5        # Proxemic (Approach 노드 social_distance)
abort_threshold: 1.0          # abort 거리
phrases:
  icebreak: { ko: [...], en: [...] }
  offer:    { ko: [...], en: [...] }
  leadin:   { ko: [...], en: [...] }
face_expression:
  icebreak: hello             # pinky_emotion 8 어휘 매핑
  offer: interest
  leadin: happy
default_language: ko
```

### Step 2: persona_manager_node.py

`src/dobi_npc/dobi_npc_dialog/dobi_npc_dialog/persona_manager_node.py`:

- **YAML 로드 + 상속 머지** — `_resolve_inheritance()` 재귀 + `_deep_merge()` 깊이 머지

- entry_point: `persona_manager`
- data_files: `config/personas/*.yaml` → share install
- 의존성: `ament_index_python`, `python3-yaml`

### Step 3: BT 노드 dialog 통합

`IceBreak`, `Offer`, `LeadIn` 모두 동일 패턴으로 변경:

```cpp
class IceBreak : public BT::SyncActionNode {
public:
  IceBreak(name, config, rclcpp::Node::SharedPtr ros_node)
  : ..., node_(ros_node)
  {
    pub_ = node_->create_publisher<std_msgs::msg::String>("/dialog/request", 10);
  }
  BT::NodeStatus tick() override {
    std_msgs::msg::String msg;
    msg.data = "icebreak";  // stage_id
    pub_->publish(msg);
    return BT::NodeStatus::SUCCESS;
  }
};
```

`bt_executor_node.cpp` 등록 변경:
```cpp
factory.registerNodeType<IceBreak>("IceBreak", node);  // 가변 인자
factory.registerNodeType<Offer>("Offer", node);
factory.registerNodeType<LeadIn>("LeadIn", node);
```

`CMakeLists.txt`/`package.xml`: `std_msgs` 의존성 추가.

빌드 10.5s 통과.

## 2. 핵심 학습 (개념 정리)

### 페르소나 상속 머지

Isla 2005 character hierarchy를 YAML로 구현:
- 자식이 `parent: <id>` 명시
- `_resolve_inheritance()`가 부모를 재귀 머지
- `_deep_merge()`로 dict는 깊이 머지, scalar/list는 자식 우선

이렇게 하면 **자식 YAML에는 변경분만** 적으면 됨. 예: `friendly_child.yaml`에서 `approach_distance: 1.2`만 override하면 나머지는 generic 상속.

### Phrase pool 분리

phrase pool과 phrase **선택 로직**을 분리:
- pool = YAML (정적 데이터)
- 선택 = `random.choice()` (Phase 5 학습 기반 추천 시 교체 지점)

### BT ↔ Dialog 비동기 통신

BT 노드가 dialog와 직접 통신하지 않고 **토픽으로 분리**:
- BT: `/dialog/request` publish (stage_id만)
- persona_manager: `/dialog/request` 구독 → phrase 선택 → `/dialog/utter` publish
- Phase 2 TTS: `/dialog/utter` 구독 → 음성 출력

이러면:
- BT는 페르소나 데이터에 의존 안 함 (관심사 분리)
- TTS도 BT/persona_manager 둘 다 모름 — 그냥 utter 토픽만 봄
- 운영 중 페르소나 전환이 BT 재시작 없이 즉시 반영

### 가변 인자 등록 일반화

W2 Step B에서 Approach만 적용했던 패턴이 W3에서 IceBreak/Offer/LeadIn까지 확장됨. **ROS 노드 핸들이 필요한 BT 노드는 모두 동일 패턴**:
```cpp
factory.registerNodeType<NodeT>("Name", node);
```
→ 생성자 시그니처: `NodeT(name, config, rclcpp::Node::SharedPtr)`

## 3. 발견 / 위험 요소 / 갭

### 발견

- **백그라운드 노드 잔재가 검증 오염**: 이전 테스트의 persona_manager 인스턴스가 `pkill -f` 후에도 잠시 살아있어, Test 4 로그에 두 페르소나 phrase가 동시 출력. 본질 동작은 정상이나 검증 명료성을 흐림.
- **BT 한 사이클이 매우 빠름**: Approach fallback 후 IceBreak/Offer/LeadIn이 **0.4ms 안에 모두 SUCCESS** (timestamp 906862, 906939, 906996). 운영 시 TTS 통합되면 발화 대기 시간이 자연스러운 박자가 될 것이지만, 검증 단계에선 phrase가 빠르게 쏟아짐.
- **Approach fallback 분기에서 dialog publish 발생**: BT funnel이 끝까지 진행되어 자연스러운 phrase 발화. 단, 실제 손님 없을 때도 phrase가 발화되는 셈 → Phase 2 IdleScan에 실 손님 검출 로직이 들어와야 호객 발화가 의미 있음.

### 위험 요소

- **영어 phrase 미검증**: 4개 페르소나 모두 ko/en 둘 다 작성했지만 검증은 ko만. `language:=en`으로 띄워 영어 분기도 점검 필요 (선택 작업).
- **랜덤 phrase 선택의 균등성**: `random.choice()`는 균등 분포. 현실에선 가중치 부여(첫 인사용 vs 재방문용 등)가 자연스러움 → Phase 5 학습 기반에서 결정.
- **YAML 스키마 검증 부재**: 잘못된 형식의 YAML이 들어오면 KeyError로 무너질 수 있음. Phase 2 진입 전 jsonschema 또는 pydantic 검증 추가 검토.

### 갭 (계획서 W3 명세 vs 실제)

- 계획서 line 195~198 "phrase pool 한국어+영어 각 3개씩" → 실제 페르소나별 1~3개 차등 (충분).
- **face_expression LCD 통합 미완**: pinky_emotion 8어휘 매핑은 YAML에 정의되어 있지만 실제 LCD 발행 미연결. **Phase 2 또는 W2.5(RPi 통합) 시점에 처리**.
- **TTS 미통합**: `/dialog/utter`는 발행하지만 음성 변환은 Phase 2.
