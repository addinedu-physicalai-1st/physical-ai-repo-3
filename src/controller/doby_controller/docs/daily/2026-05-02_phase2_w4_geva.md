**신규 추가** — Russell V·A 매핑 (EyeCon에 없음):

```python
EMOTION_VA = {
    "happy":    (+0.8, +0.5),
    "sad":      (-0.7, -0.4),
    "angry":    (-0.6, +0.7),   # abort 트리거 영역 (V<-0.5 ∧ A>0.4)
    "surprise": (+0.2, +0.8),
    "fear":     (-0.7, +0.6),   # abort 트리거 영역
    "disgust":  (-0.7, +0.2),
    "neutral":  (0.0,  0.0),
}
```
- 7감정 점수의 가중평균으로 단일 (V, A) 출력
- confidence = top emotion score
- flags = `["top:<emotion_name>"]` (디버깅용)
- 얼굴 미검출 시 → V=A=0, conf=0, flags=`["no_face"]`

**노드 구조**:
- `cv2.VideoCapture(camera_index)` 1개 + `FaceLandmarker.create_from_options(IMAGE)` 1개
- `create_timer(1.0/publish_rate_hz)` — 매 tick마다 캡처→detect→publish
- 5초마다 frames/Hz/face_detect_rate 진단 로그
- `destroy_node()`에서 cap.release() + landmarker.close()
- 견고한 main() 패턴 (CLAUDE.md §5.1) 준수

## 2. 핵심 학습 (개념 정리)

### MediaPipe FaceLandmarker IMAGE 모드의 단순함

EyeCon은 RunningMode.IMAGE를 사용 (per-frame independent inference). VIDEO/LIVE_STREAM 모드는 콜백/타임스탬프 관리가 복잡함. 우리는 ROS Timer로 캡처 주기를 통제하므로 IMAGE 모드가 적합 — `landmarker.detect(mp_image)`가 동기 호출.

### Blendshapes 52개의 의미

MediaPipe FaceLandmarker는 478점 얼굴 mesh + Apple ARKit 호환 52 Blendshapes를 출력. Blendshapes는 0~1 범위의 facial action 강도 (예: `mouthSmileLeft`, `browInnerUp`, `eyeWideRight`). EyeCon의 7감정 분류는 이 52개 중 약 15개 핵심 Blendshape의 선형결합 룰. 학술적으론 FACS(Facial Action Coding System)의 Action Unit과 1:1은 아니지만 근사.

### Russell V·A의 3가지 매핑 방식

1. **이산 좌표** (우리 v1): 7감정 → 7개 (V, A) 점, 점수 가중평균 → 단일 좌표
2. **연속 회귀**: 학습된 모델이 직접 (V, A) 출력 (예: AffectNet 기반)
3. **확률 분포**: 7감정 확률 → V·A 평면의 확률 분포

v1은 이산 좌표 + 가중평균. confidence는 top emotion score를 사용하지만 엄밀히 말하면 **분산 기반 신뢰도** (분포가 좁으면 확신, 넓으면 불확실)가 더 정확. Phase 5 학습 기반에서 (2) 또는 (3)으로 교체 검토.

### 의존성 격리: user-site의 함정

`pip install --user`는 시스템 오염을 줄이지만 **user site가 시스템 site보다 import 우선순위가 높음**. mediapipe 같은 패키지가 numpy/opencv를 같이 끌어오면, 시스템 ROS의 numpy 1.x/cv2 4.6 환경이 사일런트하게 깨짐. **transitive 의존성을 의도적으로 제거**하는 절차가 필요.

CI/재현 환경에서는 이걸 자동화해야 함 — `requirements.txt`에 `pip uninstall` 단계까지 명시. 또는 `--no-deps` 플래그로 transitive 차단 후 필요한 것만 명시 설치 (단, mediapipe의 진짜 필요 의존성 — protobuf, jax 등 — 을 빠뜨리면 안 됨).

### `/emotion/state` 토픽 분리의 가치

GEVA는 카메라 1개 분석만 담당. Phase 2 후속:
- **GEFA**: `/emotion/state` (source="body") — RPi USB 캠 자세/접근 (W2.5+)
- **decision_rule_node**: 위 두 토픽 구독 → Salichs fusion → `/emotion/state` (source="fused") 발행
- **rapport_tracker / EmotionMonitor BT**: fused 결과만 구독

이렇게 하면 GEFA 도입 전에도 GEVA만으로 BT abort 트리거 검증이 가능 (decision_rule이 단일 입력만 있으면 그대로 forward).

## 3. 발견 / 위험 요소 / 갭

### 발견 1: package.xml `<description>` 유니코드가 colcon parser를 깨뜨림

**증상**:
- `colcon build` 통과
- `ros2 run dobi_npc_emotion geva_node` → `Package 'dobi_npc_emotion' not found`
- `ros2 pkg list`에는 dobi_npc_emotion이 나타남
- 그러나 `AMENT_PREFIX_PATH`에 dobi_npc_emotion 누락
- `install/dobi_npc_emotion/share/dobi_npc_emotion/hook/`에 `ament_prefix_path.sh`가 **생성되지 않음**
- `package.dsv`에 ament_prefix_path source 라인 누락

**원인**: `<description>Dobi NPC emotion — GEVA (face → V·A), Phase 2 W4</description>`의 `—` (em-dash) `→` `·` 등 유니코드 특수문자가 colcon의 `package_xml` 파서를 silent하게 깨뜨려 `<build_type>ament_python</build_type>`을 인식 못 함. 결과적으로 ament_python build flow의 `ament_prefix_path` hook 생성 단계가 skip됨.

**해결**: description을 ASCII로 단순화 (`Dobi NPC emotion - GEVA (face to V-A), Phase 2 W4`).

**왜 빠르게 못 찾았나**:
- 빌드 자체는 stderr 없이 통과
- `ros2 pkg list`엔 패키지가 나옴 (ament_index marker는 정상 install)
- `pythonpath.sh` hook은 정상 생성
- 비교 대상 dialog 패키지는 `<description>TODO: Package description</description>` (ASCII)로 정상 동작

**기록 위치**: `CLAUDE.md §7`에 "package.xml 작성 함정" 섹션 신설. 한글/특수문자는 README나 회고 .md에 기록.

### 발견 2: mediapipe의 transitive 의존성이 ROS 환경을 깬다

**증상**: `pip install --user mediapipe==0.10.14` 직후 `python3 -c "import rclpy, cv_bridge"` 실패. NumPy 2.4.4와 1.x 컴파일 모듈의 ABI 불일치.

**원인**: mediapipe 0.10.14 wheel의 의존성 metadata가 numpy를 unpinned로 요구 → pip resolver가 최신 (2.4.4) 설치. cv2도 mediapipe가 `opencv-contrib-python>=4`로 요구.

**해결**: `pip uninstall --yes numpy opencv-contrib-python`로 transitive만 제거. mediapipe는 user-site 그대로 유지.

**검증**:
```python
import sys, numpy, cv2, mediapipe
# python: 3.12.3
# numpy: 1.26.4 @ /usr/lib/python3/dist-packages/...   ← 시스템
# cv2: 4.6.0 @ /usr/lib/python3/dist-packages/...      ← 시스템
# mediapipe: 0.10.14                                    ← user site
```
ROS sourcing 격리 셸에서도 `rclpy + cv_bridge + sensor_msgs + mediapipe` 모두 import 성공.

### 위험 요소

- **표정 변화에 따른 동적 V·A 검증 미흡**: 평범 표정에서 V=-0.27, A=0.31이라는 정적 한 점만 확인. 실제로 웃기/찡그리기 시 V·A가 어느 좌표로 이동하는지 다음 세션에서 사용자가 카메라 앞에서 표정 짓는 검증 필요. (검증 시 `ros2 topic hz /emotion/state`로 발행 주기, `ros2 topic echo /emotion/state`로 좌표 변동 동시 관찰).
- **Russell 좌표값의 학술 정확도**: 현재 좌표는 Posner 2005 근사 + 직관. 학술적으로 정확한 좌표는 표정-인지 연구마다 차이가 있음. Phase 5에서 학습 데이터로 보정 검토.
- **얼굴 1개만 감지 (`num_faces=1`)**: 카페 시나리오에서 다중 손님이 있을 때 누구의 표정을 분석할지 미정. Phase 4 파일럿 전에 정책 결정 필요 (가까운 사람? 정면 응시자?).
- **조명/거리/마스크에 대한 강건성 미검증**: 노트북 실내 조명 1조건만. 카페 환경(역광, 측면 조명, 마스크 착용 손님)에서 Blendshapes 추출 신뢰도 저하 가능성.

### 갭 (계획서 W4 명세 vs 실제)

- 계획서 W4의 GEFA(자세/접근/회피)는 **RPi 부재로 미착수** — W2.5/W4.5 별도 트랙으로 분리.
- decision_rule_node (Salichs 2014 fusion)도 GEFA 없이 단일 forward 형태로만 가능 → ② EmotionMonitor 단계에서 처리.
- TTS는 별도 트랙(③)으로 분리.
